# Запуск сервиса Orbit

Команда `orbit_service.py` создаёт локальные настройки и запускает существующий bridge. Она сохраняет токены между перезапусками, поэтому для повторного запуска не нужно заново переносить секрет в iPhone.

Понадобятся Python 3.10 или новее, установленный официальный Codex CLI и действующий вход на том компьютере, где будет работать сервис. Python-пакеты устанавливать не требуется. Авторизация Codex остаётся на этом компьютере; пароль ChatGPT в Orbit вводить не нужно.

Все команды ниже выполняются из каталога проекта.

## Запуск одной командой

Войдите через официальный CLI, если вход ещё не настроен:

```sh
codex login
```

Запустите сервис:

```sh
python3 bridge/orbit_service.py run --state .orbit/service --port 8765
```

При первом запуске команда получает список облачных задач, создаёт настройки и отдельные токены записи для найденных проектов. Затем запускает bridge на `127.0.0.1:8765`. При следующих запусках существующие токены и сводки сохраняются. Если получить данные Codex не удалось, сначала проверьте вход и соединение на этом компьютере.

Чтобы остановить сервис, нажмите **Ctrl+C**. Команда не устанавливает системную службу и не добавляет запуск при входе в macOS. Терминал и компьютер должны оставаться доступны, пока нужен сервис.

## Адрес для iPhone

Локальный HTTP-адрес предназначен для HTTPS reverse proxy на этом же компьютере или сервере. iPhone подключается к прямому HTTPS-адресу с доверенным сертификатом, например `https://your-domain.example/snapshot`, где пример нужно заменить своим доменом.

Настройте домен и HTTPS-прокси по [основной инструкции bridge](../bridge/README.md#обновлять-данные-по-https). Он должен передавать запросы на `127.0.0.1:8765`, сохраняя заголовок `Authorization`. Для отправки сводок также нужен метод `PUT` на `/briefs`. Если вы выбрали другой порт, укажите его и в настройках прокси.

Запуск одной командой не создаёт домен, сертификат или публичный сервер. В этой среде публичный сервис не развёртывался.

## Перенести подключение в iPhone

Создайте профиль с конечным HTTPS-адресом вашего снимка:

```sh
python3 bridge/orbit_service.py connection --state .orbit/service --endpoint https://your-domain.example/snapshot --output .orbit/orbit-connection.json
```

Профиль содержит адрес и **токен чтения снимков**. Он сохраняется с правами `0600`; команда не выводит токен в терминал. Сохраняйте его вне каталога `.orbit/service`: запись профиля в служебный каталог и его подпапки отклоняется, чтобы не повредить настройки или сводки. Передайте файл на свой iPhone через AirDrop или приватное хранилище в «Файлах».

В Orbit откройте экран **«Источник данных»**, импортируйте профиль подключения, проверьте адрес сервиса и нажмите кнопку подключения. Импорт заполняет настройки для проверки; получение данных начинается после подключения. Токен сохраняется в Keychain iPhone.

Профиль имеет формат:

```json
{
  "format": "orbit-connection",
  "version": 1,
  "endpoint": "https://your-domain.example/snapshot",
  "token": "REPLACE_WITH_READ_TOKEN"
}
```

Это только описание структуры. Для своего подключения используйте файл, созданный командой, и храните его приватно. Токен даёт доступ ко всему снимку, поэтому профиль не нужно передавать агенту отдельного проекта или добавлять в репозиторий. Адрес должен быть HTTPS, без логина, пароля, query string и фрагмента.

## Проверить состояние

В другом окне терминала выполните:

```sh
python3 bridge/orbit_service.py status --state .orbit/service --port 8765
```

Команда обращается только к локальному `/health`. Она сообщает, доступен ли сервис и получен ли хотя бы один снимок, не читая названия проектов или отчёты. До первого успешного опроса статус готовности будет отрицательным. Код завершения `0` означает готовность, `2` — работающий сервис без успешного снимка, `1` — ошибку или недоступный сервис. Для нестандартного порта используйте то же значение `--port`, что при запуске. Готовность локального сервиса сама по себе не проверяет внешний HTTPS-прокси и доступ с iPhone.

## Где хранятся настройки

В каталоге состояния находятся:

| Путь | Содержимое |
| --- | --- |
| `config.json` | Версия формата и токен чтения снимков |
| `writers.json` | Отдельный токен записи для каждого разрешённого `projectId` |
| `briefs/` | Принятые сводки агентов |
| `snapshot.json` | Последний сохранённый снимок |

Каталог создаётся с правами `0700`, файлы настроек — `0600`. Секреты Codex CLI в него не копируются. Для запуска bridge токен чтения временно передаётся через окружение процесса, а не через аргументы командной строки.

Путь `.orbit` уже исключён из Git. Существующие корректные настройки повторная инициализация сохраняет. Символьные ссылки и некорректные файлы настроек отклоняются; сначала проверьте каталог состояния вместо удаления или пересоздания секретов наугад.

## Добавить новый проект

После первоначальной настройки новые проекты могут появляться в облачном снимке, но право записи для них выдаётся отдельно. Получите точный `id` проекта из снимка Orbit и выполните:

```sh
python3 bridge/orbit_service.py add-project --state .orbit/service --project-id REPLACE_WITH_PROJECT_ID
```

Команда проверяет наличие проекта через Codex CLI, добавляет новый токен записи атомарно и сохраняет токен чтения и токены остальных проектов. Повторное добавление того же ID ничего не меняет. Для проверки по уже полученному файлу можно передать `--snapshot`:

```sh
python3 bridge/orbit_service.py add-project --state .orbit/service --project-id REPLACE_WITH_PROJECT_ID --snapshot .orbit/base-snapshot.json
```

Перезапустите работающий сервис после изменения списка токенов: настройки записи загружаются при запуске. Для доступа новых проектов используется тот же файл подключения iPhone.

Токен нужного проекта находится в приватном `writers.json`. Перенесите только его в секрет окружения соответствующего облачного агента `ORBIT_PROJECT_WRITE_TOKEN`. Этот токен позволяет отправлять сводки своего проекта и не даёт читать снимки. Порядок настройки и команда публикации описаны в [PUBLISHING.md](../bridge/PUBLISHING.md).

Если первоначальный снимок пустой, сервис создаётся без токенов записи и работает для чтения. Добавьте проект явно после его появления.

## Явная инициализация и вымышленный пример

Настройки можно создать заранее, не запуская listener:

```sh
python3 bridge/orbit_service.py init --state .orbit/service
```

Для первоначальной настройки по готовому снимку укажите `--snapshot`. В комплекте есть вымышленный пример, который позволяет попробовать создание настроек без обращения к аккаунту:

```sh
python3 bridge/orbit_service.py init --state .orbit/demo-service --snapshot AgentOrbit/Resources/example-cloud-snapshot.json
```

Все проекты и задачи в этом примере синтетические. Для настоящих проектов используйте отдельный каталог состояния, созданный по данным своего аккаунта. Даже после инициализации из файла команда `run` продолжает опрашивать настоящий Codex CLI; параметр `--snapshot` не превращает её в демонстрационный сервер.

Этот launcher не собирает и не подписывает приложение iPhone. Проверка сборки, установка через Xcode и ограничения TestFlight описаны в [BUILD.md](BUILD.md).
