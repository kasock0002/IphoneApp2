# Orbit 0.5 — проекты Codex на iPhone

[![iPhone build checks](https://github.com/kasock0002/IphoneApp2/actions/workflows/ios-check.yml/badge.svg)](https://github.com/kasock0002/IphoneApp2/actions/workflows/ios-check.yml)

Нативное приложение для iPhone с iOS 17 и новее. Русский интерфейс, 3D-карта, анимация агентов, карточки проектов, раскрывающиеся отчёты и следующие шаги. Рабочее название — Orbit.

## Что добавлено в этой версии

- Запуск локального сервиса одной командой `python3 bridge/orbit_service.py run`: приватная настройка при первом старте, сохранение ключей при следующих запусках.
- Файл подключения для iPhone: сервис экспортирует адрес и ключ в приватный JSON; приложение импортирует его в форму для проверки и подтверждения.
- Команды `status` и `add-project`: проверка локального сервиса и выдача доступа новому проекту с сохранением существующих ключей.
- Проверен настоящий локальный HTTPS-путь от клиента отправки до снимка для читателя с синтетическими данными и временными сертификатами.
- Отправка сводок агентом по HTTPS без ручного переноса файла. Для записи выдаётся отдельный токен конкретного проекта, который не позволяет читать снимки или обновлять другие проекты.
- Защита от замены новой сводки старой, идемпотентные повторы и проверка размера всего снимка до сохранения. Принятая сводка будит фоновый цикл сервиса; повторные запросы объединяются, не вызывая отдельный опрос CLI каждый раз.
- Лента трёх последних отчётов со всех проектов на главном экране; нажатие открывает проект.
- Проверка настоящей сборки для iPhone Simulator на macOS через GitHub Actions. Результат виден по статусу выше; workflow не создаёт подписанное приложение для физического iPhone.
- Сводки от агентов: этап, прогресс, состав команды, отчёты и следующие шаги дополняют список облачных задач через `--briefs-dir`.
- Время наблюдения и автор сводки показаны отдельно от времени опроса Codex. Обновление списка задач не делает старую сводку новой.
- Команда `validate-briefs` проверяет объединение без аккаунта и может создать файл для просмотра на iPhone. Есть готовый вымышленный пример.
- Получение снимков по HTTPS, отдельный токен сервиса в Keychain, ручное обновление и опрос примерно раз в минуту при активном приложении.
- Адаптер `bridge/orbit_bridge.py`: читает задачи через официальный Codex CLI, собирает страницы ответа и группирует задачи по окружениям.
- Облачные задачи показаны отдельно от агентов. Отсутствующие этап, прогресс и даты отображаются как неизвестные. Количество попыток задачи не используется как число агентов.
- Последний успешный снимок сохраняется на iPhone. При ошибке обновления данные остаются доступны, а интерфейс сообщает о сбое или устаревшем ответе сервиса.
- Импорт и деморежим приостанавливают автообновление. Настройки подключения остаются в Keychain до явного отключения сервиса.

**Это исходники приложения и сервиса, а не подписанная сборка для установки.** Сервис не развёрнут. При предыдущей проверке аккаунта CLI получил HTTP 401 из-за недействующей авторизации среды. Работающий вход Codex CLI нужен на компьютере пользователя, где будет запущен адаптер.

## Запуск на iPhone

Понадобятся Mac с Xcode 16 или новее и iPhone с iOS 17 или новее.

Короткая последовательность установки приложения и подключения сервиса: [docs/QUICKSTART.md](docs/QUICKSTART.md).

1. Откройте `AgentOrbit.xcodeproj`. Для самого приложения внешних пакетов нет.
2. В target **Orbit → Signing & Capabilities** выберите свою Team. При необходимости замените Bundle Identifier `app.orbit.projectdesk` на уникальный.
3. Подключите iPhone, подтвердите доверие компьютеру и включите режим разработчика, если Xcode попросит.
4. Выберите iPhone и нажмите **Run**. Для iPhone Simulator подпись не нужна.

ZIP с исходниками нельзя установить на iPhone как готовое приложение. Для установки нужна сборка и подпись Apple. Для TestFlight понадобится участие в Apple Developer Program.

## Подключить облачный Codex

Рекомендуемый запуск и экспорт профиля: [docs/SERVICE.md](docs/SERVICE.md). Настройка HTTPS и низкоуровневый режим сервиса: [bridge/README.md](bridge/README.md).

Есть два варианта:

1. На компьютере с авторизованным Codex CLI выполните `python3 bridge/orbit_bridge.py export --output orbit-snapshot.json`. Передайте файл на iPhone и импортируйте через экран источника данных.
2. Запустите `python3 bridge/orbit_service.py run`, настройте свой HTTPS reverse proxy и экспортируйте профиль командой `connection`. Передайте файл на iPhone и выберите **Источник данных → Импортировать подключение**. Проверьте адрес и подтвердите подключение. Ручной ввод адреса и ключа также доступен.

В приложении не нужен пароль ChatGPT или API-ключ OpenAI. Авторизация CLI остаётся на компьютере с адаптером. Приложение принимает только HTTPS, блокирует перенаправления, не записывает токен в URL и не сохраняет сетевой кеш.

Карточки облачного источника соответствуют окружениям Codex. Это не автоматическое чтение раздела «Проекты» и чатов ChatGPT. Полный состав агентов, подробные проектные отчёты, этапы и будущие шаги CLI-списком не подтверждены и не выдумываются. Для них нужно подключить отдельный достоверный источник или передать их в формате снимка. Подробнее: [INTEGRATION.md](INTEGRATION.md).

## Передать сводку агента

Инструкция и готовый запрос агенту: [bridge/BRIEFS.md](bridge/BRIEFS.md). Агент формирует JSON со временем наблюдения и ID проекта. Его можно перенести в каталог сервиса либо отправить через `bridge/publish_brief.py` по HTTPS. Настройка отдельного токена записи и приёмника описана в [bridge/PUBLISHING.md](bridge/PUBLISHING.md). Секрет проекта задаётся в окружении агента; сервис и HTTPS должны быть настроены заранее. Автоматическое чтение внутреннего состояния облачных агентов не реализовано.

Готовый пример без аккаунта:

```sh
python3 bridge/orbit_bridge.py validate-briefs --snapshot AgentOrbit/Resources/example-cloud-snapshot.json --briefs-dir bridge/examples/demo-briefs --output .orbit/demo-combined.json
```

Файл можно импортировать на iPhone. Тот же вымышленный пример включён в приложение: **Источник данных → Пример задач со сводкой агентов**. Облачные задачи остаются нетронутыми, а сводка добавляет анимируемых агентов, отчёт, этап и будущие шаги.

## Что можно попробовать без подключения

- Откройте проект в 3D-сцене или в обычном списке.
- Посмотрите прогресс, этапы, агентов и их текущие задачи.
- Раскройте отчёты и просмотрите план работ.
- В источнике данных поделитесь примером снимка и импортируйте его обратно из «Файлов».
- Импортируйте пример облачных задач: там этап и процент отсутствуют, а не равны нулю.
- Включите iOS **Универсальный доступ → Движение → Уменьшение движения**, чтобы остановить анимацию.

Все комплектные проекты и отчёты вымышлены. `example-cloud-snapshot.json` также содержит исключительно синтетические задачи с явно примерными статусами.

## Формат данных

Схема v3: `AgentOrbit/Resources/snapshot.schema.json`. Примеры рядом: `example-snapshot.json`, `example-cloud-snapshot.json`, `example-enriched-snapshot.json`. Старый демоформат совместим. Метаданные `briefUpdatedAt` и `briefSource` должны быть заполнены вместе либо оба отсутствовать/быть `null`.

Даты — ISO 8601 с часовым поясом, с долями секунды или без них. Допустимо 0–12 проектов, до 12 агентов, до 50 отчётов и шагов, до 100 облачных задач на проект; файл до 2 МБ. Идентификаторы непустые и уникальны внутри своего списка. Прогресс — число от 0 до 1 либо `null`; этап и время обновления также могут отсутствовать или быть `null`.

Некорректный импорт не заменяет текущие данные. Снимок сохраняется атомарно с защитой файла и исключается из резервного копирования. Старые сохранённые снимки первого прототипа читаются автоматически. Последний успешный сетевой ответ сохраняется вместе с источником, временем получения и состоянием автообновления.

Файл подключения отличается от снимка проектов: это формат `orbit-connection`, версия 1, ровно четыре поля `format`, `version`, `endpoint`, `token`, размер до 16 КиБ. Он содержит ключ доступа и предназначен только для ваших устройств. Импорт заполняет форму; ключ записывается в Keychain и сетевой запрос начинается после нажатия кнопки подключения.

SceneKit рисует реальных агентов только из явно переданных записей `agents`. Задачи из `cloudTasks` не создают вымышленных роботов. На карте видно до восьми агентов на проект, весь состав доступен в карточке. Рендеринг ограничен 30 кадрами/с; анимация приостанавливается при неактивности приложения, открытии карточек и Reduce Motion.

## Проверки

Выполнены **138 Python-тестов** адаптера, сводок, HTTP-приёмника, клиента отправки и настройки сервиса, включая реальный локальный TLS с проверкой сертификата. Проверены примеры по JSON Schema, plist/XML, ресурсы и ссылки Xcode-проекта. Python-тесты используют синтетические данные, не реальный аккаунт. TLS-тесты требуют установленный `openssl`.

```sh
python3 -m unittest discover -s bridge -v
```

Модели Foundation, декодер и профиль подключения **скомпилированы в официальном контейнере Swift 6.0.3**, все **28 XCTest-тестов прошли**, включая ленту отчётов и новый формат подключения. Синтаксический разбор 12 Swift-файлов приложения также прошёл. Дополнительно фактический профиль, экспортированный Python-сервисом на тестовых данных, прочитан Swift-декодером без вывода ключей. Повторить проверку ядра в Docker можно через `scripts/check-swift-container.sh` после явной загрузки образа `swift:6.0.3-jammy`.

На Mac выполните проверку ядра и настоящую сборку приложения:

```sh
swift test
xcodebuild -project AgentOrbit.xcodeproj -scheme Orbit -sdk iphonesimulator -configuration Debug -derivedDataPath build CODE_SIGNING_ALLOWED=NO build
```

Локальная Cloud-среда работает на Linux. Настоящую сборку UIKit/SwiftUI/SceneKit проверяет macOS workflow; его результат и журналы доступны по ссылке вверху. На своём Mac можно выполнить `sh scripts/check-macos.sh`. Запуск интерфейса и установка на физический iPhone требуют отдельной проверки: навигации, импорта, обновления, сохранения после перезапуска и остановки анимации в фоне.

Автоматическая проверка macOS и путь к установке описаны в [docs/BUILD.md](docs/BUILD.md). Репозиторий проекта — [kasock0002/IphoneApp2](https://github.com/kasock0002/IphoneApp2). Архив симулятора нельзя установить на физический iPhone.
