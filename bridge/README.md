# Подключение облачного Codex к Orbit

Адаптер получает облачные задачи через документированную команду **Codex CLI** `codex cloud list --json`, собирает все страницы ответа и создаёт JSON-снимок для iPhone-приложения. Пароль ChatGPT и авторизация CLI остаются на компьютере, где запущен адаптер.

Нужны Python **3.10+**, установленный официальный Codex CLI и работающая авторизация `codex login` на этом компьютере. Python-пакеты устанавливать не требуется. Семейство команд `codex cloud` экспериментальное, поэтому изменение формата ответа останавливает обновление с понятной ошибкой, сохраняя предыдущие данные.

Для обычного запуска используйте новый помощник: `python3 bridge/orbit_service.py run`. Он создаёт приватные ключи при первом запуске, сохраняет их и умеет экспортировать файл подключения для iPhone. Полная последовательность: [../docs/SERVICE.md](../docs/SERVICE.md). Команды ниже оставлены для ручной настройки самого bridge.

## Что появится в приложении

Задачи группируются по `environment_id`: карточка проекта здесь соответствует **окружению Codex**, а не автоматически установленному соответствию разделу «Проекты» в ChatGPT. Задачи без указанного окружения находятся в общей карточке «Облачный Codex».

В карточке есть название задачи, сырой статус, известное время обновления, строковая сводка и безопасная ссылка на задачу в `chatgpt.com`. Неизвестные значения остаются неизвестными. `attempt_total` не превращается в число агентов; из статуса задачи не вычисляются этап или процент готовности. Состав агентов, подробные проектные отчёты и будущие шаги не выдумываются.

Для явных сведений от агентов добавлен каталог сводок `--briefs-dir`. Он дополняет существующий проект этапом, агентами, отчётами и планом; время наблюдения сохраняется отдельно. Формат, проверка и запрос агенту описаны в [BRIEFS.md](BRIEFS.md). Без этого флага поведение облачного адаптера сохраняется.

Лимиты формата Orbit: до 12 окружений, до 100 задач в окружении, 2 МБ на снимок. При превышении адаптер сообщает ошибку и **не обрезает** список незаметно. Для большого аккаунта можно выбрать одно окружение через `--env ENVIRONMENT_ID`. Повторяющиеся курсоры, дубликаты идентификаторов и незавершённая пагинация также останавливают замену снимка.

## Получить файл без сервера

Запустите из каталога проекта на компьютере с авторизованным CLI:

```sh
python3 bridge/orbit_bridge.py export --output orbit-snapshot.json
```

Для конкретного окружения:

```sh
python3 bridge/orbit_bridge.py export --output orbit-snapshot.json --env ENVIRONMENT_ID
```

Передайте файл на iPhone через «Файлы»/AirDrop и импортируйте его в Orbit. Это именно снимок на указанное время, а не обновление в реальном времени. Новый файл атомарно заменяет старый только после успешного получения всех данных; на Unix он создаётся с правами `0600`.

## Обновлять данные по HTTPS

Bridge слушает **только локальный IPv4 loopback**. Для iPhone нужен HTTPS-адрес с доверенным сертификатом; TLS завершается на отдельном reverse proxy на вашем компьютере/сервере. HTTP listener нельзя открыть через `--host 0.0.0.0`.

1. Создайте отдельный секрет bridge. Это не пароль ChatGPT и не токен Codex CLI:

   ```sh
   export ORBIT_BRIDGE_TOKEN="$(python3 -c 'import secrets; print(secrets.token_urlsafe(32))')"
   ```

   Сохраните это значение в своём менеджере паролей для переноса в приложение. В macOS его можно скопировать без вывода в терминал:

   ```sh
   printf '%s' "$ORBIT_BRIDGE_TOKEN" | pbcopy
   ```

2. Запустите bridge в том же окружении:

   ```sh
   python3 bridge/orbit_bridge.py serve --snapshot .orbit/snapshot.json --refresh-seconds 60
   ```

   `ORBIT_BRIDGE_TOKEN` должен содержать от 32 до 512 печатных ASCII-символов без пробелов. Секрет принимается только из переменной окружения, не из аргументов командной строки. Его нужно сохранять самостоятельно между перезапусками сервиса. Пересоздание переменной на новом запуске требует обновить токен в приложении.

3. Настройте свой HTTPS reverse proxy, проксирующий на `127.0.0.1:8765` с сохранением заголовка `Authorization`. Например, блок Caddy для **вашего** домена:

   ```caddyfile
   orbit.example.com {
       reverse_proxy 127.0.0.1:8765
   }
   ```

   Этот пример не создаёт домен, DNS или сервер автоматически. Хост и сертификат должны уже быть доступны для настройки. Не включайте запись заголовка `Authorization` в логи прокси.

4. В настройках источника Orbit укажите `https://ваш-домен/snapshot` и отдельный токен bridge. Приложение обращается к этому HTTPS-адресу; URL с токеном в query string не используется.

Команда `serve` обновляет снимок последовательно, по таймеру; HTTP-запросы сами не запускают CLI. Один вызов CLI ограничен 30 секундами. `Ctrl+C`/`SIGTERM` останавливают цикл; если уже выполняется запрос CLI, завершение может занять до его тайм-аута.

## HTTP-контракт

| Запрос | Ответ |
| --- | --- |
| `GET /snapshot`, `Authorization: Bearer …` | `200 application/json` с полным снимком |
| `GET /snapshot` без корректного секрета | `401`, без данных аккаунта |
| `GET /snapshot` до первого успешного получения данных | `503 snapshot_not_ready` |
| `GET /health` | `200 {"ready":true/false}`; без названий и количества задач |

Все ответы содержат `Cache-Control: no-store`. После неудачного обновления bridge продолжает отдавать **последний успешный снимок** с исходным `generatedAt` и заголовком `X-Orbit-Stale: true`. Успешный новый снимок получает `X-Orbit-Stale: false`. Сохранённый на диске старый файл не выдаётся как новый после перезапуска: до первого успешного опроса сервер отвечает `503`.

Пути `/snapshot` и `/health` точные; query string и неизвестные пути отвергаются. CLI stderr, заголовки авторизации и данные аккаунта не попадают в сообщения bridge. Коды ошибок CLI нужно разбирать на авторизованном компьютере; при проблемах входа выполните `codex login` самостоятельно.

## Проверка

```sh
python3 -m unittest discover -s bridge -v
```

Тесты используют **синтетические ответы CLI** и временный HTTP listener на loopback. Они проверяют пагинацию, неизвестные поля, группировку, ограничения, отсутствие выдуманного прогресса, атомарное сохранение, Bearer-авторизацию, устаревшие данные и ошибки. Реальный аккаунт в тестах не вызывается.

В среде разработки реальное чтение аккаунта пока не подтверждено: CLI достиг сервиса, но получил HTTP 401 из-за недоступной здесь авторизации. Работу с вашим аккаунтом нужно проверить на хосте с действующим входом CLI. Адаптер не развернут на публичном сервере.
