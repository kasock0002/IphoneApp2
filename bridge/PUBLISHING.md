# Отправка сводки из облачного агента

Агент может отправить подготовленную сводку в Orbit по HTTPS, без переноса файла вручную. Он выполняет отдельную команду публикации; внутреннее состояние облачных агентов приложение по-прежнему автоматически не читает.

Формат сводки, правила времени и пример запроса агенту описаны в [BRIEFS.md](BRIEFS.md). Отправляйте только наблюдаемые результаты. Если этап, прогресс или состав агентов неизвестны, не придумывайте их.

## Настроить приём на компьютере с bridge

Нужны действующий вход Codex CLI, настроенный HTTPS reverse proxy и существующий `projectId` из снимка Orbit. Авторизация CLI остаётся на компьютере с bridge.

Для отправки используется **отдельный токен конкретного проекта**. Он не является токеном чтения снимков `ORBIT_BRIDGE_TOKEN`, паролем ChatGPT или токеном Codex CLI. Создайте новый секрет длиной от 32 до 512 печатных ASCII-символов без пробелов и сохраните его в менеджере секретов.

На компьютере с bridge создайте `.orbit/writers.json`: JSON-объект, где ключ — точный `projectId`, а значение — отдельный токен записи. Ниже только заменяемые обозначения, а не рабочие данные:

```json
{
  "REPLACE_WITH_PROJECT_ID": "REPLACE_WITH_A_NEW_PROJECT_WRITE_TOKEN"
}
```

Не добавляйте файл с реальными токенами в репозиторий. Каталог `.orbit` уже исключён из Git. Ограничьте доступ к файлу владельцем:

```sh
chmod 600 .orbit/writers.json
```

Запустите сервис с приёмом сводок:

```sh
python3 bridge/orbit_bridge.py serve --snapshot .orbit/snapshot.json --briefs-dir .orbit/briefs --writer-config .orbit/writers.json
```

Если вы используете новый `orbit_service.py run`, он создаёт ключи самостоятельно и запускает этот режим за вас. Ключи записи находятся в приватном `.orbit/service/writers.json`; не создавайте второй независимый файл по пути из ручного примера. Настройка и добавление проектов: [../docs/SERVICE.md](../docs/SERVICE.md).

Переменная `ORBIT_BRIDGE_TOKEN` для чтения снимков должна быть настроена отдельно по [основной инструкции](README.md). Без `--writer-config` приём сводок не включается.

HTTPS reverse proxy должен передавать метод `PUT`, тело запроса и заголовок `Authorization` на локальный bridge. Используйте конечный адрес вида `https://your-domain.example/briefs` без перенаправлений, заменив пример своим доменом. Настройка сервиса, домена и сертификата не выполняется этой инструкцией автоматически.

До первого успешного опроса Codex сервис не знает допустимые проекты и отвечает `503`. `projectId` сводки должен присутствовать в полученном снимке. Новые проекты отправкой сводки не создаются.

## Настроить отправку у агента

Поместите токен записи этого проекта в секрет окружения облачного агента с именем `ORBIT_PROJECT_WRITE_TOKEN`. Способ добавления секрета зависит от используемого окружения Codex; эту настройку нужно выполнить отдельно. Не передавайте токен текстом задачи, аргументом команды или в URL. Агенту не нужен токен чтения всех снимков.

После формирования `project-brief.json` агент выполняет из каталога проекта:

```sh
python3 bridge/publish_brief.py --url https://your-domain.example/briefs --file project-brief.json
```

Клиент использует только стандартную библиотеку Python, поэтому дополнительные Python-пакеты не нужны. Его можно передать вместе с проектом. Он читает токен из `ORBIT_PROJECT_WRITE_TOKEN`, отправляет JSON методом `PUT` и не выводит токен, адрес сервиса или содержимое отчёта в сообщения.

Клиент принимает только HTTPS с обычной проверкой сертификата. HTTP, адреса с логином/паролем, query string и фрагментом отклоняются. Перенаправления заблокированы, чтобы токен не ушёл на другой адрес. Файл должен быть UTF-8 JSON не больше 256 КиБ; повторные JSON-ключи отклоняются.

Передавайте целую актуальную сводку проекта. Новая принятая сводка заменяет предыдущую, поэтому сохраняйте в ней те записи `agents`, `reports` и `steps`, которые должны оставаться видимыми. `observedAt` означает реальное время наблюдения; его нельзя менять только ради обхода конфликта старой записи.

## Что означает ответ

| Ответ | Действие |
| --- | --- |
| `202` | Сводка принята и сохранена. Она появится в следующем снимке и после обновления приложения; это не подтверждение мгновенной доставки на iPhone. |
| `401` или `403` | Проверьте секрет записи и соответствие `projectId`. Токен другого проекта и токен чтения не дают права записи. |
| `409` | Уже хранится более новая сводка либо другое содержимое с тем же временем наблюдения. Сначала проверьте актуальные результаты и привязку проекта. |
| `413` | Файл превышает допустимый размер. Сократите сводку, сохранив необходимые сведения. |
| `422` | Документ не соответствует формату либо итоговый снимок со всеми сводками превысит 2 МБ. Проверьте поля, даты и объём данных по `BRIEFS.md`. |
| `503` | Сервис ещё не готов принимать сводку. Проверьте первоначальный опрос Codex и состояние сервиса на его компьютере. |

Повторная отправка того же принятого документа с тем же временем идемпотентна. Если соединение оборвалось без понятного ответа, можно повторить отправку неизменённого документа.

Перед записью сервис проверяет полный набор уже принятых и новой сводок на последнем известном исходном снимке Codex. Если документ не помещается в общий лимит, он не заменяет текущий файл. После принятия отдельный рабочий цикл сервиса обновляет снимок; запросы объединяются, между опросами CLI сохраняется пауза не менее 10 секунд. Изменение размера самих облачных данных позже также может привести к ошибке обновления — приложение продолжит показывать последний успешный снимок.

Режим отправки не подключает аккаунт и не разворачивает публичный сервис сам. Для работы с реальным облачным агентом нужны настроенные хост, HTTPS и секрет его проекта. Тесты клиента используют искусственные ответы и не публикуют отчёты в реальные проекты.
