# Интеграция с облачным Codex

## Реализованная схема

`Codex CLI на авторизованном компьютере → Python bridge → ваш HTTPS endpoint → iPhone`.

Bridge умеет экспортировать файл без сервера либо опрашивать CLI и отдавать последний успешный снимок. Для iPhone требуется HTTPS reverse proxy с доверенным сертификатом. Сам Python listener слушает только локальный IPv4 loopback. Развёртывание и настройка DNS не выполнялись.

Авторизация Codex остаётся на стороне CLI. Для доступа к снимкам используется отдельный токен Orbit от 32 до 512 печатных ASCII-символов без пробелов. В iOS настройки хранятся в Keychain с доступом только на разблокированном устройстве и без переноса на другие устройства. Клиент не следует перенаправлениям с токеном и принимает не более 2 МБ JSON.

HTTP-контракт, команды запуска и HTTPS-пример описаны в [bridge/README.md](bridge/README.md).

В версии 0.5 добавлен `orbit_service.py`: приватная инициализация и запуск одной командой, проверка локального статуса, добавление проекта и экспорт профиля подключения телефона. Ключ чтения сохраняется между запусками; профиль `orbit-connection` импортируется в форму приложения и требует подтверждения. Быстрый путь: [QUICKSTART.md](docs/QUICKSTART.md).

## Что можно получить

Официальный [справочник Codex CLI](https://learn.chatgpt.com/docs/cli/reference) описывает `codex cloud list --json --limit 20`, фильтр `--env` и пагинацию `--cursor`. Команды cloud экспериментальные. Ответ содержит `tasks` и необязательный `cursor`; документация перечисляет поля `id`, `url`, `title`, `status`, `updated_at`, `environment_id`, `environment_label`, `summary`, `is_review`, `attempt_total`.

Адаптер использует документированные команды CLI. Он группирует записи по `environment_id` и сохраняет строковые статусы без предположений о значениях перечисления. Строковая сводка показывается как сводка задачи; объект вместо строки не преобразуется в вымышленный текст. Неизвестные даты и ссылки остаются `null`.

Это список задач Codex, а не доказанное соответствие личным проектам ChatGPT. Отсутствие задач — корректный пустой снимок. Превышение лимитов или неполная пагинация завершают обновление ошибкой вместо незаметного усечения списка.

## Что нельзя выводить из списка задач

- `attempt_total` не является количеством агентов.
- Статус задачи не задаёт процент готовности или этап проекта.
- Сводка задачи не подтверждает наличие подробных проектных отчётов или плана будущих работ.
- Отсутствие списка агентов не означает, что агентов нет.

Поэтому базовый облачный адаптер передаёт `stage:null`, `progress:null`, пустые `agents`, `reports`, `steps`. Интерфейс явно сообщает, что источник не передал эти сведения. В версии 0.3 добавлен согласованный формат сводок агентов: [BRIEFS.md](bridge/BRIEFS.md). Файлы из `--briefs-dir` заполняют только явно переданные поля существующего проекта и не меняют облачные задачи. Сводка содержит собственные время наблюдения и автора; интерфейс показывает их отдельно. В файловом режиме документ переносит пользователь; в версии 0.4 его также можно отправить из агента через настроенный HTTPS-приёмник.

Анимация отображает только явные записи агентов и не доказывает активность сейчас. Неверная привязка, некорректный файл или повтор ID останавливают публикацию целиком; сервис сохраняет последний успешный снимок с признаком устаревших данных. Проверка `validate-briefs` работает с готовым снимком без обращения к аккаунту.

В версии 0.4 сводку можно отправить через HTTPS `PUT /briefs`: [PUBLISHING.md](bridge/PUBLISHING.md). Для этого нужен отдельный токен записи только одного проекта; он не позволяет читать снимок. Запись доступна после первого успешного опроса Codex, проверяется по известным ID, времени и общему лимиту размера до атомарного сохранения. Принятие HTTP 202 означает сохранение документа, а не мгновенную доставку на телефон. Реальный публичный сервис и секреты облачного агента здесь не настраивались.

[Agents API](https://developers.openai.com/api/docs/guides/agents-api/overview) описывает отдельные API-сессии приложения. Доступ через этот API к существующим личным задачам и проектам ChatGPT нами не подтверждён, поэтому приложение его не использует. [Экспорт ChatGPT](https://help.openai.com/en/articles/7260999-exporting-your-chatgpt-history-and-data) — архив, не источник живого обновления.

## Состояние проверки

Официальные страницы и справка установленного CLI проверены 15 ноября 2026 года. Установлен `codex-cli 0.167.0-alpha.4`; `codex cloud list --help` подтверждает нужные флаги.

В этой итерации реальный запрос CLI достиг сервиса, но получил **HTTP 401** из-за недействующей авторизации текущей среды. Формат реального ответа аккаунта и доступность полей **не подтверждены живыми данными**. На хосте пользователя нужно выполнить вход через официальный CLI и проверить экспорт.

138 автоматических тестов Python проверили синтетические ответы, пагинацию, неизвестные значения, ошибки, токены, приём и отправку сводок, общий лимит, настройку сервиса и устаревший снимок. Два теста использовали настоящий локальный TLS с временным доверенным сертификатом, стандартный клиент отправки, цикл обновления и HTTPS-чтение снимка. Недоверенный сертификат отклонялся. Примеры соответствуют JSON Schema v3.

В официальном контейнере Swift 6.0.3 скомпилировано Foundation-ядро и выполнены 28 XCTest-тестов без ошибок; синтаксический разбор всех 12 Swift-файлов прошёл. Фактический тестовый профиль подключения, созданный Python-сервисом, также прочитан Swift-кодом. Эти проверки не подтверждают работу iPhone/URLSession на устройстве. Настоящая сборка UI на macOS проверяется в [GitHub Actions](https://github.com/kasock0002/IphoneApp2/actions/workflows/ios-check.yml); результат и журналы доступны по ссылке. Физическое устройство и подпись Apple проверяются отдельно.

Приложение обновляет снимок при активном интерфейсе и сохраняет последний результат. Push-уведомления и фоновое обновление iOS пока не реализованы.
